## Verification and limits

Final product revision: `c5a2e83226619f551c576d736a7b616d9ec577cf`. Full pytest: **323 passed in135.69s**; configured coverage gate: **179 passed,76.87% coverage** (70% floor). Ruff, diff checks, Node syntax, offline examples, wheel/sdist build and installed-wheel15-tool/drum workflow passed. Dependency audit after updating isolated pip: no known vulnerabilities found in audited dependencies; the local project is source-audited rather than available on PyPI. Both audit workers approved the corrected source;153 focused tool tests and184 DSP/output selections passed during review. Detailed commands and delivery handoff: tasks/current-session.md and docs/verification.md. This audit is a source review plus behavioral verification, not proof of absence of all defects.

Accepted boundaries: arrangement frame cap is a duration bound, not a RAM byte quota; more tracks/effect tails/trace candidates use more memory. No-overwrite publication requires filesystem hard-link support and fails safely otherwise (no unsafe fallback). Stem collision handling does not establish Windows reserved-device-name portability. PRJ003 describes explicit base-track/standalone-preset controls; it does not add section-only option findings. Seven supported GM percussion pitches are imported; other kit mappings require explicit future design. Trace audibility/pitch limitations are disclosed, not inferred away. Native Windows/macOS binaries, physical playback/OS volume, signing/notarization and remote release workflows require external verification. No public release/tag/deployment was performed.
